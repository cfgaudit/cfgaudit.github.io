    Known attacks

    Which published attacks on coding agents depend on something a repository file can carry, and what cfgaudit reports for that file. cfgaudit detects the configuration an attack depends on, not the bug behind it. Most of these CVEs are agent bugs fixed in a release, so a finding means the file has the shape the attack used, not that a current agent is vulnerable.

    {{.Advisories.Full}} are detected, {{.Advisories.Partial}} partly, and {{.Advisories.None}} are not, each with the reason. Every listed rule and severity is checked against a fixture in cfgaudit's tests. Bugs in servers and model behaviour are left out, because no configuration file shows them.

    Accessibility

    This site works toward WCAG 2.2 Level AA. On each change every page must score 100 in Lighthouse's accessibility audit and pass axe, in both the light and the dark theme, and changes are reviewed by hand too, because an automated score can't tell whether a page is actually usable.

    The site runs no JavaScript. It is semantic HTML with a skip link, visible keyboard focus, text that stays legible when you zoom, and wide tables and code blocks you can scroll with the keyboard.

    cfgaudit the command-line tool has its own accessibility properties: severity is always a word, never colour alone, colour is optional and off in a pipe, and every finding is available in machine-readable formats for a screen reader or a script. The full statement, for the tool and this site, is ACCESSIBILITY.md in the main repository.

    If something here stops you from using cfgaudit, please open an accessibility issue and tell us what you were doing, which tool and assistive technology you used with versions, and what got in the way.
